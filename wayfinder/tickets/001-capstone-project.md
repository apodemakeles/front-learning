## Question

贯穿课程的综合实战项目（毕业项目）做什么？需要与学员一起敲定：

- **项目方向**：候选——① 贴近公司业务的门店 / 餐饮管理后台；② 通用型任务或客户管理系统；③ 学员自己想做的项目
- **功能范围**：至少覆盖 登录 + 路由守卫、列表分页查询、新建 / 编辑表单、删除确认、一屏图表；是否再加 权限菜单、文件上传、WebSocket 等
- **前后端关系**：课程提供现成 mock API，还是学员自建后端（学员是资深后端，可自己写一个）
- **与部署工单的联动**：毕业项目最终要部署上线，形态（纯前端 + mock / 全栈）影响部署课的内容

## Notes

- HITL 工单：需要学员在线，一问一答（grilling）推进，agent 不得代答。
- 选型结果将直接决定「课程大纲定稿」（005）中各课作业围绕什么展开。

## Resolution

2026-09-05 与学员四问四答定稿：

1. **项目**：一个**虚拟门店的轻量管理后台**——场景纯属教学虚构，不追求业务真实。
2. **技术形态**：Vue 3 + Vite + Pinia + Vue Router + Element Plus + TypeScript（版本按 `notes/tech-baseline.md` 基准），中后台标配布局。
3. **功能 = 基础功能包**：登录 + 路由守卫、商品列表（分页/筛选）、商品新建/编辑表单、删除确认、一屏经营数据看板（图表）。**不加**动态权限菜单、文件上传、WebSocket 等增强项；某课需要额外教学载体时，随课用独立小 demo 解决，不进毕业项目。
4. **数据 = mock 主线**：课程提供现成 mock 数据层，API 层抽象为可替换；结业阶段**可选**接学员自建后端，作为部署课的联调实战（选修，不占主线课时）。
5. **部署形态**：默认纯静态部署即可上线；具体部署环境由工单 003 决定。

**附带确立的课程级原则**（已同步至 AGENTS.md）：示例的业务场景为教学服务、可以虚拟，不必贴近公司业务；但技术选型与工程形态必须贴近公司真实栈。
