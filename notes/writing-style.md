# 课程写作风格与流程指南（写课工单必读）

> 本文件把第 1 课确立的写作惯例显式化，供任何会话 / 任何 AI 续写课程时遵循。规则层面见 [AGENTS.md](../AGENTS.md)，骨架见 [templates/lesson-template.md](../templates/lesson-template.md)，版本见 [notes/tech-baseline.md](tech-baseline.md)。

## 读者与视角

- 读者是 20 年经验的 Java 后端老兵（也是本仓库的学员本人）：**平视对话**，HTTP / Maven / JVM / Linux / Docker 默认都熟，绝不解释这些
- 可以直接对"你"说话、可以点名学员的真实处境（"你上班维护的存量项目"），但**仓库里不得出现公司内部信息**（AGENTS.md 保密纪律）

## 动笔前：实测纪律（最重要的一条）

1. 课文里每条命令先在本机（macOS / Node 24 / pnpm 11）真实运行一遍
2. 预期输出的"关键行"从实测拷贝，**不得凭记忆或想象编造**
3. 改动指引精确到文件与位置（"src/App.vue 第 13 行附近"）——先打开真实文件确认再写
4. 版本数字以 tech-baseline 为准；与实测不一致时，以实测为准并回填基准文件
5. 示例代码放 `demos/NN-slug/`（第 1 课这类"学员自己脚手架生成"的项目除外，不入库）

## 笔法基调

- 中文行文，技术名词保留英文
- **类比优先**：新概念先给后端对照（优先用 AGENTS.md 类比表）；一个类比通常只用一次，点破即止，不反复咀嚼
- **心智模型 > 细节**：原理部分先立"模型"再给"证据"（实测输出、文件实物）；
- **不剧透**：后面课程才深讲的机制，一句话"第 N 课讲"带过，不提前展开复杂度
- 步骤精确、零猜测：学员照做应该一路绿灯；报错高发点提前预警
- 克制的幽默可以有；宁可拆课，不可灌水

## 结构内的固定惯例

- 开头元信息行：`> 所属模块：… ｜ 前置课程：… ｜ 预计用时：… ` + 版本基准行（含 tech-baseline 链接）
- "本课目标"≤3 条，每条以"你能…"开头、可验收
- 正文需要时回顾上节课成果（"上一课你跑起来的那个项目"）；作业尽量接续上节课的产物
- "原理深入"= 2–3 个编号心智模型，每个一两段
- 作业：任务清单 + 验收 checkbox，**验收的是"现象"不是"理解"**（能看到什么，而不是能想通什么）
- 延伸阅读只放官方一手资料
- 表格用于"两国对照"、命令清单这类枚举型内容，叙述用散文

## 发布流程（每课一循环）

1. 认领工单（assignee 署名）
2. 实测本课全部命令与改动点
3. 套模板写 `lessons/NN-english-slug.md`
4. README：目录中该课课题加链接并改 ✅，更新进度行（N/38）
5. 关闭工单：Resolution 记录**实测事实**（命令、输出关键行、版本）与产出链接
6. 提交推送，commit 信息格式：`第N课发布：<课题>（命令实测）；进度N/38，工单XXX关闭`

## 交接（新会话 / 换 AI 时的开工顺序）

1. 读 `AGENTS.md` → `wayfinder/map.md`（Decisions so far 与 Notes）→ 本文件 → `notes/tech-baseline.md`
2. 在 `wayfinder/tickets/` 找 frontier 工单（open、blocked-by 全 closed、无 assignee）
3. 读最近发布的 1–2 课找语感（不必全读）
4. 按发布流程执行；一次会话推进一课
